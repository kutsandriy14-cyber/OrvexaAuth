# Ручной выпуск OrvexaAuth Android

## Принцип

В репозитории **не используется GitHub Actions workflow** для Android. APK собирается локально постоянным release-ключом, а GitHub Release создаётся и заполняется вручную. Это исключает автоматические сборки и автоматическую публикацию.

## Сборка

Из корня репозитория выполнить:

```bash
printf 'sdk.dir=/home/ubuntu/android-sdk\n' > local.properties
./gradlew :app:assembleRelease
rm -f local.properties
```

Перед выпуском убедиться, что в `app/build.gradle.kts` увеличены `versionCode` и третья цифра `versionName` — например, `0.1.3` → `0.1.4`. Использовать нужно только `app/build/outputs/apk/release/app-release.apk`, подписанный постоянным ключом OrvexaAuth. Сам ключ и `signing.properties` нельзя добавлять в GitHub Release или репозиторий.

## Создание Release

Создать вручную GitHub prerelease с тегом `v0.1.X` и приложить подписанный APK под именем:

```text
OrvexaAuth-Beta-0.1.X.apk
```

GitHub API добавляет SHA-256 digest к ассету. OrvexaAuth Beta 0.1.3 и новее принимает только APK с этим именем, из HTTPS-пути официального GitHub Release и только когда digest соответствует скачанному файлу.

Для единственного переходного релиза **v0.1.3** также приложить идентичную копию этого же APK под именем `app-debug.apk`. Это требуется только для Beta 0.1.2: её старый встроенный поиск обновлений ожидает именно это имя. Начиная с 0.1.3, файл `app-debug.apk` больше не используется приложением и не должен добавляться к новым релизам.

> Установка всегда требует явного действия пользователя: приложение лишь находит обновление и открывает стандартное подтверждение Android. Скрытая установка не выполняется.
