# OrvexaAuth Admin — техническая спецификация v1

## Границы продуктов

| Продукт | Назначение | Чего в нём нет |
|---|---|---|
| `OrvexaAuth` | Пользовательский вход, профиль, безопасность и обычные социальные функции | Административных экранов, административного токена и маршрутов управления |
| `OrvexaAuth Admin` | Отдельное Android-приложение для уполномоченных операторов | Обычного пользовательского входа, публичного веб-доступа и встроенного `ADMIN_SECRET` |
| Cloudflare Worker | Единственный источник прав, журналов, экспортов и операций модерации | Доверия к данным, присланным приложением без серверной проверки |

## Модель доступа

Админ-приложение использует обычный вход OrvexaAuth и временный токен, вводимый оператором для текущего сеанса. Worker сверяет его только со своим серверным `ADMIN_SECRET`, затем создаёт отдельную короткоживущую админ-сессию на 15 минут. Токен админ-сессии существует только в памяти приложения, привязан к устройству и не записывается в SharedPreferences, Keystore или экспорт.

`ADMIN_SECRET` остаётся только серверным средством выпуска временной админ-сессии. Он никогда не добавляется в APK, репозиторий, `.ac`, `.chat` или запросы пользовательского OrvexaAuth; приложение передаёт введённый оператором временный токен только на защищённый серверный маршрут.

## Защита передачи данных

Все вызовы Android-приложений идут только через `https://` с TLS; приложение отклоняет незащищённые URL. Для привилегированных операций Worker дополнительно проверяет короткоживущую админ-сессию, уникальный идентификатор запроса, время запроса и роль. Повторно использованный идентификатор запроса отклоняется. Это защищает от повторной отправки опасной команды даже при ошибке клиента.

> Шифрование TLS защищает данные при передаче. Сквозное шифрование чатов нельзя включать для модерируемых серверных чатов без потери возможности серверной проверки и удаления; поэтому оно не будет имитироваться небезопасным «двойным шифрованием».

## Административная операция удаления сообщения

В интерфейсе операция находится в отдельном журналируемом разделе **Модерация**, визуально похожем на служебный исходящий канал. Это не скрытое сообщение и не команда в пользовательском чате. Запрос выполняется как `POST /api/admin/messages/{messageId}/redact` и всегда содержит обязательную причину.

Worker выполняет только мягкое удаление: заменяет текст маркером удаления, сохраняет неизменяемые метаданные сообщения, время удаления, идентификатор админ-сессии и причину. В публичном чате текст становится недоступен, но в журнале не сохраняется его содержимое. Удаление требует отдельного подтверждения в приложении и создаёт запись аудита.

## Формат `.ac` — экспорт аккаунтов

Файл `.ac` является UTF-8 JSON-документом с версионированной схемой. Он содержит только минимальные административные сведения об аккаунтах; не содержит пароли, passwordHash, токены, TOTP-секреты, активные сессии, ключи и резервные коды.

```json
{
  "format": "orvexa.account-export",
  "schemaVersion": 1,
  "createdAt": "2026-08-18T12:00:00Z",
  "scope": "selected-accounts",
  "accounts": [
    {
      "id": "123456",
      "displayName": "Example User",
      "status": "active",
      "createdAt": "2026-08-01T12:00:00Z",
      "lastLoginAt": "2026-08-18T10:00:00Z"
    }
  ],
  "integrity": { "algorithm": "SHA-256", "digest": "hex-digest-of-canonical-payload" }
}
```

Экспорт с персональными данными, если он когда-либо потребуется, должен быть отдельной серверной ролью, отдельным действием подтверждения и отдельным ключом области `scope`; по умолчанию такое поле отсутствует.

## Формат `.chat` — экспорт архива переписки

Файл `.chat` является UTF-8 JSON-документом с версией схемы. Он поддерживает личные и групповые диалоги и сохраняет записи об удалении как tombstone, не восстанавливая скрытый текст.

```json
{
  "format": "orvexa.chat-export",
  "schemaVersion": 1,
  "createdAt": "2026-08-18T12:00:00Z",
  "conversation": { "type": "direct", "id": "u1_and_u2" },
  "messages": [
    {
      "id": "42",
      "senderId": "u1",
      "sentAt": "2026-08-18T11:59:00Z",
      "text": "Visible message"
    },
    {
      "id": "43",
      "senderId": "u2",
      "sentAt": "2026-08-18T12:00:00Z",
      "redacted": true,
      "redactedAt": "2026-08-18T12:01:00Z",
      "reasonCode": "policy-violation"
    }
  ],
  "integrity": { "algorithm": "SHA-256", "digest": "hex-digest-of-canonical-payload" }
}
```

Импорт `.ac` и `.chat` по умолчанию выполняется в режиме предпросмотра. Он не создаёт аккаунты, не меняет переписку на сервере и не восстанавливает удалённые сообщения. Применение серверных изменений требует отдельной привилегированной операции.

## Аудит

Каждая операция администрирования записывает `eventId`, время, тип действия, целевой объект, идентификатор короткоживущей админ-сессии, причину и результат. Пароли, токены и удалённое содержимое сообщений не записываются в аудит. Журнал доступен только роли администратора и экспортируется отдельно от `.ac` и `.chat`.
