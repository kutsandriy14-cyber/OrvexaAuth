# Проверка виртуальной LAN-игры Orvexa через интернет

## Назначение

Этот сценарий проверяет именно обычный одиночный мир Minecraft Java, открытый командой **«Открыть для сети»**. Отдельный Minecraft-сервер, проброс портов на роутере, публичный IP и сторонние туннели не нужны. Локальный TCP-порт игры передаётся через защищённое соединение `wss://orvexaauth-api.bot724524.workers.dev` и ретранслятор Cloudflare.

## Что нужно до начала

| Сторона | Необходимо |
|---|---|
| Хост | Актуальная сборка Orvexa Launcher, Minecraft Java, учётная запись OrvexaAuth и одиночный мир. |
| Гость | Актуальная сборка Orvexa Launcher, Minecraft Java той же версии и набора модов, отдельная учётная запись OrvexaAuth. |
| Сеть | Две разные интернет-сети. Например, домашний Wi‑Fi хоста и мобильный интернет/другая домашняя сеть гостя. Оба клиента должны иметь исходящий HTTPS/WSS-доступ к `orvexaauth-api.bot724524.workers.dev`. |
| Доступ | Аккаунты должны быть принятыми друзьями в OrvexaAuth. Для режима `invite` хост добавляет гостя в приглашение к миру. |

## Действия хоста

1. Войти в Orvexa Launcher под своим OrvexaAuth-аккаунтом и запустить нужную Minecraft-сборку.
2. Открыть одиночный мир и в меню паузы выбрать **«Открыть для сети»**. Minecraft напишет локальный порт в чат и в `logs/latest.log`; Launcher читает этот порт автоматически.
3. Вернуться в Launcher, открыть вкладку **«Социальное»** и в карточке **«Виртуальная LAN-игра»** создать LAN-сеанс. Указать название мира, режим доступа `friends` или `invite`; для `invite` добавить друга.
4. Дождаться статуса, что хостовый туннель открыт. Не закрывать Launcher: он поддерживает локальный TCP↔WSS-мост, пока игра запущена.

## Действия гостя

1. Войти в Orvexa Launcher под приглашённым аккаунтом и открыть **«Социальное»**.
2. Обновить список активных LAN-сеансов. После первого создания список может появиться с небольшой распределённой задержкой Cloudflare KV; если мир не виден сразу, повторить обновление через 15–30 секунд.
3. Выбрать мир друга и нажать **«Подключиться»**. Launcher получает одноразовый WSS-пропуск, создаёт локальный адрес `127.0.0.1:<порт>` и запускает Minecraft с этим адресом.
4. В Minecraft проверить вход в тот же мир, перемещение, чат, взаимодействие с блоками и минимум пять минут непрерывной игры.

## Критерии результата

| Проверка | Ожидаемый результат |
|---|---|
| Доступ извне | Гость подключается из другой сети без публичного IP хоста, VPN, проброса порта и выделенного Minecraft-сервера. |
| Авторизация | Неприглашённый пользователь не видит закрытый `invite`-мир и не может получить пропуск подключения. |
| Поток игры | Хост и гость видят действия друг друга; чат, чанки и игровые пакеты проходят в обе стороны. |
| Повторное подключение | После выхода гостя хост остаётся в мире, а гость может запросить новый пропуск и подключиться заново. |
| Закрытие | После закрытия LAN-сеанса хостом локальный мост и WSS-соединения завершаются; дальнейшее подключение невозможно. |

## Что прислать при сбое

Нужно прислать без паролей, session token и WSS-ссылок: роль клиента (хост/гость), шаг, текст ошибки Launcher, версию Minecraft/загрузчик модов, и последние 40–60 строк `logs/latest.log`. Для Launcher также полезны последние строки его журнала. Этого достаточно, чтобы отличить проблему совместимости Minecraft-сборок от сетевого транспорта.

> Автоматическая публичная проверка уже подтвердила создание приглашённого сеанса, выдачу отдельных одноразовых WSS-пропусков, соединение двух сторон через Cloudflare Durable Object, двунаправленную передачу бинарных кадров, запрет повторного использования пропуска и закрытие обоих соединений после завершения сеанса. Этот сценарий остаётся последней проверкой с настоящими Minecraft-клиентами.
