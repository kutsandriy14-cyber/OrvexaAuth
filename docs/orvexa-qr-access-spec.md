# Orvexa QR Access v1

## Назначение

**Orvexa QR Access** позволяет владельцу вручную выпускать QR-изображения для входа в отдельный OrvexaAuth Admin. Пользователь Admin выбирает ранее полученный файл через системный файловый диалог. Камера, обычный OrvexaAuth-логин и пароль в Admin не используются.

QR-файл — это **передаваемый доступ**, а не учётная запись OrvexaAuth и не замена обычной регистрации. Ник и метка владельца служат для понятного отображения, но не являются доказательством прав. Право подтверждает только выданный сервером непрозрачный одноразовый секрет.

## Разделение приложений

| Приложение | Роль | Хранит ли секрет QR-доступа |
|---|---|---|
| **Orvexa QR Access Generator** | Приложение владельца: создаёт, отображает, сохраняет, перечисляет и отзывает QR-доступы. | Только во время сохранения конкретного изображения; впоследствии отображается лишь метаинформация. |
| **OrvexaAuth Admin** | Принимает файл QR через Storage Access Framework и открывает краткий админ-сеанс. | Нет. Расшифрованные данные живут только в памяти до обмена на сеанс. |
| **Cloudflare Worker** | Выпускает, проверяет, привязывает к устройству, отзывает QR-доступы и записывает аудит. | Хранит только SHA-256 хеш секрета, а не сам секрет. |

## Модель доверия

При первом запуске генератора владелец вручную вводит **bootstrap-секрет владельца**. Он не включается в APK, QR, логи, Android-хранилище или репозиторий. Worker принимает этот секрет только для регистрации публичного ключа конкретного генератора.

Генератор создаёт RSA-2048 ключ в Android Keystore. Закрытая часть не экспортируется. После регистрации последующие запросы генератора подписываются закрытым ключом; Worker проверяет подпись по сохранённому публичному ключу. Поэтому для ежедневной выдачи и отзыва QR не нужны ни пароль OrvexaAuth, ни повторный ввод bootstrap-секрета.

> Потеря или удаление данных генератора требует повторной регистрации нового ключа владельцем. Старый ключ отзывается сервером.

## Формат QR

QR хранит UTF-8 JSON, затем кодируется в QR-код. Формат не содержит `ADMIN_SECRET`, пароль, email, закрытый ключ или постоянный серверный токен.

```json
{
  "format": "orvexa.qr-access",
  "schemaVersion": 1,
  "accessId": "uuid",
  "credential": "256-bit random base64url value",
  "nickname": "Отображаемый ник",
  "label": "Необязательная метка владельца",
  "scopes": ["accounts.read", "audit.read"],
  "expiresAt": "2026-09-01T12:00:00.000Z"
}
```

Секрет `credential` создаётся Worker, а в KV хранится только его SHA-256 хеш. QR имеет статус `active`, `revoked` или `expired`. По умолчанию доступ может быть активирован только на одном Android-устройстве: при первом успешном обмене Worker сохраняет SHA-256 идентификатора устройства и отклоняет последующие устройства.

## Набор прав

Генератор выдаёт только явно выбранные права. По умолчанию все права выключены.

| Право | Возможность в OrvexaAuth Admin |
|---|---|
| `accounts.read` | просмотр и поиск реестра учётных записей |
| `accounts.restrict` | ограничение и восстановление доступа |
| `accounts.delete` | необратимое удаление учётной записи |
| `chat.moderate` | мягкое удаление текста сообщений |
| `exports.write` | экспорт `.ac` и `.chat` |
| `audit.read` | просмотр журнала аудита |

## Серверные операции

Все запросы Generator после регистрации подписаны. Worker требует идентификатор выдающего ключа, свежую метку времени, уникальный `requestId`, подпись от канонического тела и защиту от повторного исполнения.

| Маршрут | Назначение |
|---|---|
| `POST /api/qr-access/issuers/enroll` | однократная регистрация публичного ключа Generator с bootstrap-секретом |
| `POST /api/qr-access/issue` | выпуск QR и возврат единственного экземпляра секрета |
| `GET /api/qr-access/issued` | список метаданных выданных QR без секретов |
| `POST /api/qr-access/{accessId}/revoke` | отзыв доступа с обязательной причиной |
| `POST /api/qr-access/exchange` | обмен выбранного QR на 15-минутный, привязанный к устройству сеанс Admin |

Выдача, отзыв, первая активация, отклонённый обмен и успешный обмен обязательно записываются в `admin_audit`. Успешный обмен создаёт временный `admin_session`, содержащий только выбранные права.

## Ограничения

- QR-изображение следует передавать только доверенному человеку. Оно действует как физический пропуск до первого обмена или отзыва.
- После отзыва, истечения срока либо попытки с другого устройства QR отклоняется Worker.
- Ни Generator, ни Admin не сохраняют расшифрованный QR в настройках, базе данных или журнале приложения.
- Android Admin прекращает сеанс при закрытии процесса; серверный сеанс действует не более 15 минут.
